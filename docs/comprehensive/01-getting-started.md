## 사전 요구사항 / Prerequisites

**한국어:**
로컬 개발 환경에서 백엔드와 프론트엔드를 동시에 실행하려면 아래 도구가 필요합니다.

**English:**
The following tools are required to build and run both backend and frontend locally.

| 도구 | 버전 | 설치 확인 |
|---|---|---|
| Go | 1.25.6 | `go version` |
| Node.js | 18 이상 | `node --version` |
| npm | 9 이상 (Node 동반) | `npm --version` |
| sqlc | v2 (latest) | `go run github.com/sqlc-dev/sqlc/cmd/sqlc@latest version` |
| UPX | any | `upx --version` — 빌드 바이너리 압축용 (제거 제안 금지) |
| Docker | optional | 컨테이너 배포 전용, 로컬 개발 불필요 |
| Turso CLI | optional | 원격 DB 스키마 조회 시 사용 |
| golangci-lint | latest | CI 필수, 로컬에서도 `make lint` 권장 |

## 환경변수 설정 / Environment Variables

**한국어:**
`.env` 파일을 프로젝트 루트에 생성하세요. `.env.development`는 Vite 전용(프론트엔드 프록시 설정)이므로 Go 서버 변수는 별도 `.env`에 작성합니다. `unit-test.sh`는 `.env`를 자동 로드합니다.

**English:**
Create `.env` at the project root. `.env.development` is Vite-only (frontend proxy). Go server env vars belong in `.env`. `unit-test.sh` auto-sources `.env`.

### 필수 환경변수 / Required Variables

| 변수 | 설명 | 예시 |
|---|---|---|
| `TURSO_DATABASE_URL` | Turso libsql DSN | `libsql://your-db.turso.io` |
| `TURSO_AUTH_TOKEN` | Turso 인증 토큰 (기밀) | `eyJ...` |
| `GEMINI_API_KEY` | Google Gemini API Key | `AIza...` |
| `GOOGLE_CLIENT_ID` | OAuth2 클라이언트 ID | `xxx.apps.googleusercontent.com` |
| `GOOGLE_CLIENT_SECRET` | OAuth2 시크릿 | `GOCSPX-...` |
| `AUTH_SECRET` | 세션 쿠키 서명 키 | 32자 이상 랜덤 문자열 |
| `APP_BASE_URL` | OAuth callback base URL | `https://your-domain.com` |
| `SLACK_TOKEN` | Slack Bot Token | `xoxb-...` |
| `WHATAP_LICENSE` | WhaTap 라이선스 키 | `xxx-yyy-zzz` (whatap.conf 또는 env) |

### 선택 환경변수 / Optional Variables

| 변수 | 기본값 | 설명 |
|---|---|---|
| `LOG_LEVEL` | `INFO` | DEBUG / INFO / WARN / ERROR |
| `PORT` | `8080` | HTTP 리슨 포트 |
| `GEMINI_ANALYSIS_MODEL` | `gemini-3-flash-preview` | Task 추출 모델 |
| `GEMINI_TRANSLATION_MODEL` | `gemini-3.1-flash-lite` | 번역 모델 |
| `TURSO_SYNC_URL` | — | 로컬 SQLite ↔ Turso 동기화 URL |
| `TURSO_SYNC_INTERVAL` | — | 동기화 간격 (e.g. `5m`) |
| `AUTO_ARCHIVE_DAYS` | `7` | 자동 아카이브 기준일 |
| `STALE_THRESHOLD_WORKING_DAYS` | `3` | 스테일 판정 기준 근무일 |
| `TELEGRAM_APP_ID` | — | Telegram MTProto App ID |
| `TELEGRAM_APP_HASH` | — | Telegram MTProto App Hash |
| `NOTION_TOKEN` | — | Notion 통합 토큰 |
| `NOTION_REPORT_PAGE_ID` | — | 리포트 저장 페이지 ID |
| `INTERNAL_SCAN_SECRET` | — | `/api/internal/scan` 인증 키 |
| `COMPANY_DOMAINS` | — | 콤마 구분 (e.g. `corp.com,team.io`) |
| `GMAIL_SKIP_SENDERS` | — | 무시할 발신자 패턴 목록 |
| `AUTH_DISABLED` | `false` | `true`시 인증 우회 (개발용) |

| `WEEKLY_REPORT_ENABLED` | `false` | Weekly Report 활성화 |

## 빌드 / Build

### Makefile 타겟 표 / Makefile Targets

| 타겟 | 동작 |
|---|---|
| `make` / `make build` | FE + BE 병렬 빌드 (`-j2`) |
| `make build-backend` | Go 백엔드 빌드 → UPX 압축 → `./message-consolidator` |
| `make build-frontend` | Vite 프론트엔드 빌드 → `dist/` |
| `make build-mc-util` | CLI 유틸 빌드 → `./mc-util` |
| `make run` | 빌드 후 즉시 실행 |
| `make install-service` | systemd 서비스 등록·기동 (VPS용) |
| `make uninstall-service` | 서비스 중지·삭제 |
| `make status` | `systemctl status message-consolidator.service` |
| `make logs` | `journalctl -u ... -n 100 -f` |
| `make test-go` | `go test ./...` |
| `make test-ui` | `npm test` (vitest) |
| `make test-ai` | AI 관련 파일 변경 감지 시 regression 실행 |
| `make test-ai-force` | AI regression 강제 실행 |
| `make test-all` | Go + UI + AI 병렬 실행 (`-j3`) |
| `make sqlc-gen` | `sqlc generate` (= `make sqlc-gen`) |
| `make lint` | `golangci-lint run ./...` |
| `make lint-fix` | `golangci-lint run --fix ./...` |
| `make clean` | 테스트 아티팩트 정리 |

**한국어:**
백엔드 빌드는 `CGO_ENABLED=0`으로 정적 링크됩니다. `whatap-go-inst` 자동 주입 도구는 gorilla/mux 비호환으로 제거되었으며, `go build` 직접 사용이 강제됩니다.

**English:**
Backend builds with `CGO_ENABLED=0` (static binary). `whatap-go-inst` auto-instrumentation was removed due to gorilla/mux incompatibility — `go build` is used directly.

→ 빌드 스크립트: [Makefile:13-20](../../Makefile#L13)

## DB 쿼리 재생성 / sqlc Generate

**한국어:**
`db/*.sql.go`는 sqlc가 자동 생성합니다. **직접 수정 금지**. 쿼리 변경 흐름은 아래와 같습니다.

**English:**
`db/*.sql.go` is auto-generated by sqlc. **Never edit directly.** The workflow for query changes:

```bash
# 1. SQL 쿼리 편집
vi store/queries/messages.sql

# 2. Go 코드 재생성
make sqlc-gen

# 3. 의도치 않게 변경된 파일 원복
git checkout db/schema.sql.go   # 필요한 경우
```

> `sqlc generate` 후 변경된 파일을 `git diff`로 확인하고, 의도한 변경만 스테이징하세요.

## 테스트 / Testing

### 전체 테스트

```bash
bash unit-test.sh          # Go + NPM + AI regression + UI verify 병렬 실행
```

`unit-test.sh`는 `.env`를 자동 로드하며, 4개 스위트를 병렬 실행하고 실패 로그만 출력합니다.

### 개별 실행

```bash
go test ./...              # 전체 Go 테스트
npm test                   # vitest 단위 테스트
make test-ai-force         # AI regression 강제 실행 (변경 감지 없이)
make lint                  # golangci-lint (CI 필수)
```

**한국어:**
AI regression 테스트(`-tags regression`)는 `ai/` 또는 `tests/regression/` 파일 변경 감지 시에만 자동 트리거됩니다. 강제 실행이 필요하면 `make test-ai-force`를 사용합니다.

**English:**
AI regression tests (tagged `regression`) auto-trigger only when files under `ai/` or `tests/regression/` change. Use `make test-ai-force` to run unconditionally.

## 로컬 개발 모드 / Local Dev

**한국어:**
백엔드와 프론트엔드를 동시에 실행합니다. Vite dev server는 `/api` 요청을 Go 서버로 프록시합니다.

**English:**
Run backend and frontend simultaneously. Vite dev server proxies `/api` requests to the Go server.

```bash
# 터미널 1 — Go 백엔드
go run .

# 터미널 2 — Vite 프론트엔드 dev server
npm run dev
```

프론트엔드는 `http://localhost:5173`에서 실행되며, `.env.development`의 `VITE_API_BASE_URL=/api`가 Go 서버(`:8080`)로 프록시합니다.

## 첫 코드 변경 워크플로 / First Change Workflow

**한국어:**
브랜치 생성 → 코드 수정 → (DB 변경 시) sqlc 재생성 → 테스트 → 커밋 순서를 따릅니다.

**English:**
Branch → edit code → (if DB changed) regenerate sqlc → test → commit.

```bash
git checkout -b feat/my-feature

# 코드 수정 ...

# DB 쿼리 변경 시만
make sqlc-gen
git diff db/          # 의도한 변경인지 확인

# 테스트
bash unit-test.sh
make lint

# 커밋 (PR은 직접 생성)
git add <specific-files>
git commit -m "feat: ..."
```

## 트러블슈팅 / Troubleshooting

**한국어:** 빈번한 로컬 개발 문제와 해결 방법입니다.

**English:** Common local development issues and resolutions.

### 1. DB 락 — `database is locked`

**원인**: 여러 Go 프로세스가 동일 SQLite 파일에 동시 접근.

**해결**: `make run` 실행 전 기존 프로세스 종료 확인.
```bash
lsof | grep message-consolidator | grep -v grep
kill <PID>
```

### 2. 포트 충돌 — `bind: address already in use`

**원인**: `:8080` 이미 사용 중.

**해결**: `PORT=8081 go run .` 으로 대체 포트 사용, 또는 기존 프로세스 종료.

### 3. OAuth callback URL 불일치

**원인**: Google OAuth 콘솔의 redirect URI와 `APP_BASE_URL`이 다름.

**해결**: Google Cloud Console → OAuth 클라이언트 → "승인된 리디렉션 URI"에 `http://localhost:8080/auth/callback` 추가.

### 4. Turso 연결 지연 — 첫 쿼리 타임아웃

**원인**: Turso edge DB는 첫 연결(cold start)이 느릴 수 있음. `SELECT 1` keepalive가 이를 완화.

**해결**: 재시도 또는 `TURSO_SYNC_URL`로 로컬 SQLite 동기화 설정. `store/db.go`의 keepalive 로직 확인.

→ [store/db.go](../../store/db.go)

### 5. `sqlc generate` 후 예상치 못한 파일 변경

**원인**: sqlc가 `db/schema.sql.go` 등 건드리지 않아야 할 파일을 재생성.

**해결**: `git checkout db/<file>` 로 원복 후 커밋에서 제외.
